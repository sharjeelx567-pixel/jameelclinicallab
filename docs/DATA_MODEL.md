# Data model (Cloud Firestore)

Document shapes are defined in `backend/src/common/entities.ts`. Timestamps are ISO-8601 UTC strings generated by the API server. Identifiers are opaque Firestore IDs. **CNIC is never used as an identifier.**

| Collection | Key fields | Relationships / notes |
|---|---|---|
| `users/{uid}` | email, displayName, role, status | `uid` = Firebase Auth uid |
| `roles/{roleId}` | permissions[] | Overrides defaults in `common/permissions.ts` |
| `loginActivity` | uid, event, at, ip | Per-user sign-in log |
| `patients` | mrNumber, name, gender, ageYears/dateOfBirth, mobile, cnic?, address{}, status, searchTokens[] | `referringDoctorId → doctors`, `panelId → insurancePanels` |
| `doctors` | name, clinic, commission{} | |
| `insurancePanels` | discountPercent, rates{testId: price} | |
| `testCategories` | name, sortOrder | |
| `tests` | code, categoryId, price, parameters[]{ranges[]}, analyzerMappings[] | Parameters are embedded (always read with the test). Ranges are `draft` until approved |
| `orders` | orderNumber, patientId, items[] (price snapshot, `resultId`, `sampleId`), billing{}, status, statusHistory[] | Patient name and MR are denormalised for lists and receipts |
| `samples` | sampleNumber (barcode), orderId, testIds[], status, timeline[] | |
| `results` | orderId, sampleId, testId, status, version, values[] (flag, source, range snapshot) | One per order item |
| `resultVersions/{resultId_vN}` | snapshot, approvedBy, supersededAt | Append-only approved history |
| `reports` | reportNumber, orderId, version, status, snapshot, verificationCode, printCount | Snapshot is immutable |
| `reportPrints` | reportId, channel, by, at, copy | Reprint history |
| `payments` | receiptNumber, orderId, type (payment/refund), method, amount, businessDate | `businessDate` is the lab-local date |
| `homeSamplingRequests` | requestNumber, status, collectorId, history[] | `orderId` once converted |
| `inventoryItems` / `inventoryTransactions` | quantity, minimumLevel, expiryDate / ledger | Ledger is append-only |
| `analyzers` | mode (live/demo), protocol, connectionState, bridgeId | |
| `analyzerMessages/{sha256}` | raw, status, results[], errors[] | Doc ID = hash → idempotent intake |
| `notifications` | kind, severity, audiencePermission, readBy[] | No patient names |
| `auditLogs` | action, entity, entityId, actor, at, changes | Append-only |
| `laboratorySettings/main` | profile, branches, report/barcode/billing/retention config | |
| `counters/{name}` | value | Transactional sequences: `patientMr`, `order`, `sample`, `receipt`, `refund`, `report`, `homeSampling` |
| `labelPrints` | sampleId, kind, by, at | Label reprint tracking |
| `mediaAssets` | category, ownerId?, publicId, secureUrl, width, height, bytes, uploadedBy | Cloudinary images (non-sensitive only). Indexes: (category, createdAt desc), (category, ownerId, createdAt desc) |

## Number formats

- MR: `JCL-YY######`
- Order: `ORD-YY######`
- Sample: `SYY#######`
- Receipt: `RC-YY######`
- Refund: `RF-YY######`
- Report: `RPT-YY######`
- Home sampling: `HS-YY#####`

All are allocated inside transactions, so they can't collide.

## Search

Firestore has no full-text search. Patients, orders, doctors, tests and inventory store `searchTokens` (lower-case prefixes of names, numbers, mobile and CNIC), queried with `array-contains`. This suits a single laboratory. For larger scale, add a search service such as Typesense or Algolia.

## Indexes

All composite indexes required by the backend's queries are in [`firebase/firestore.indexes.json`](../firebase/firestore.indexes.json). Deploy them with:

```bash
cd firebase && firebase deploy --only firestore:indexes
```

If a query fails in production with `FAILED_PRECONDITION`, Firestore's error message contains a link that creates the missing index. Add it to the file as well.
